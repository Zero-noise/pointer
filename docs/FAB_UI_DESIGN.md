# Pointer 设计系统 · 硝子

> 单一材质系统。`theme.css` 是唯一的真相来源；popup、options 和 FAB 的
> shadow root 都读它。这份文档解释**为什么**，数值以 `theme.css` 为准。

---

## 一、三种东西，仅此三种

任何一个像素都必须能被归到下面三类之一。归不进去的，就是不该存在的第四种材质。

| | 名字 | 是什么 | 出现在哪 |
|---|---|---|---|
| 1 | **和紙 SCENE** | 温暖的纸底。**永远不可点击** | popup / options 的 body |
| 2 | **硝子 GLASS** | 白色磨砂玻璃，只有厚度之分 | 所有控件、面板、透镜、小球、球本身 |
| 3 | **墨 INK** | 画**在**玻璃上的痕迹，自身不是材质 | 文字、发丝线、边沿、下划线、光带 |

纸就是纸：`.pointer-scene` 只铺**纹理**（纤维 grain + 漉き斑 + 簀の目），
两层都平铺，两页读同一张纸。**场景里不放图**，避免插图的固定宽高比在
popup 和 options 两种尺寸下产生不同的视觉重量。

**唯一的铁律：墨永远不变成面。**

没有任何东西被信号墨填满。它只负责"画"——一道边、一条下划线、一圈光带、
一颗旋钮、一个字。正因为如此，激活的小球、popup 的开关、options 的主按钮、
滑杆已填的那一段、一句译文下面的那条线，读起来是同一个手势的不同尺寸。

---

## 二、整套 UI 没有色相

信号色是 **濃墨**（`--accent-rgb: 31, 28, 25`），比正文墨 `--ink-1` 深一档。
层级完全由**浓淡**承担，不由色相承担。

唯一活下来的颜色是 **朱**（`--alert`），而且它活下来是有理由的：一套只有浓淡
的系统没法说"这件事失败了"——更深的墨只读作"更强调"。朱筆是读者在墨稿上批改
用的那支笔，一页黑白里的一点朱。**只画报错，永远不做 hover、不做状态。**

### 三条边界

1. **rim 不换成硬边黑圈。** 激活态保留玻璃边缘的高光，只在其上叠加墨色边沿；
   同一个物件不能在激活时突然换成另一种材质。
2. **信号不用色相。** 状态层级继续由浓淡承担，避免最显眼的激活态变成彩色发光。
3. **不用实心色面表达“生效中”。** 主按钮、滑杆和其他状态都用“染色 + 边沿”，
   保持墨是笔画而不是一整块面。

---

## 三、修法：同一块玻璃，被上了墨

玻璃本体（底色、`backdrop-filter`、落影、顶光白鳞）**一动不动**。
玻璃边缘的高光是物理事实，不该被状态覆盖。信号由三样东西承担，
全部是墨、全部是"画上去的"而不是"换掉的"：

```
1. 边沿   白鳞之上覆一层濃墨          → 是上色，不是换材质
2. 滲み   软扩散的墨晕，没有硬边      → 像墨洇进纸里
3. halo   外沿那条 8s 旋转的墨带      → 同一支墨
```

同一句话在别处的写法：

| 物件 | 怎么说"生效中" |
|---|---|
| FAB 小球 | 边沿覆濃墨 + 滲み + halo 墨带 |
| popup 开关 | 旋钮是墨珠，槽里透出 `0 0 8px` 的同源晕 |
| popup 字段（透镜已展开） | 白鳞之上覆 `--accent-rim` 边沿 + 同一条 `0 0 8px` 滲み，玻璃本体不动 |
| options 主按钮 | `--accent-tint` 染色 + `--accent-rim` 边沿 |
| options 滑杆 | 已填的一段按 `--accent-rim` 的 α 画，是 4px 笔画不是实心面 |
| 译文 | 底下一条 `--accent-rim` 下划线 |

## 四、墨必须跟着纸翻

这是"没有色相"付出的代价，也是它唯一的麻烦：**墨是靠"离纸多远"定义的**。
白纸上是黑、黑页上必须是白，没法一个值跨明暗。濃墨画在黑页上不是"弱"，
是**看不见**。

`theme.css` 的 `@media` 只知道系统偏好，而 FAB 贴在别人家页面上——系统深色、
站点白底是极常见的组合。所以 FAB 按 HSP 采样的**实际底色**翻，和图标那支墨
共用同一条 `tInk` 过渡带：

```js
// content.js · _computeAdaptiveTokens()
const tSig    = _smooth(Y);              // HSP 亮度
const signalA = _lerp(0.72, 0.42, tSig); // 边沿 α：暗底重 → 亮底轻
const glowA   = _lerp(0.20, 0.10, tSig); // 滲み α：同上
```

浓度随环境走的理由是物理的：暗底上玻璃更薄、落影更黑，同样一笔要重一档才
"落得实"。两端的 α 都比彩色信号需要的低——纯度没了，明度差在替它发力，同样
的 α 墨看上去重得多。

`content-page.css` 做不到这件事（见第八节），所以它把**两套主题全部手写出来，
hover 也不能漏**：`:hover` 规则的特指度压过 `@media` 暗色块，漏一条就会在黑页
上把那个标记重新涂成黑的。

---

## 五、深色模式不是材质切换，是 alpha 调节

同一块白玻璃：

- α 0.42 叠在白纸上 → 温柔的白雾
- α 0.10 叠在黑纸上 → 暗炭色，同一块物件，只是反差缩到暗底阈值

`backdrop-filter: blur(24px) saturate(160%)` 在任何底色上都继续是"玻璃"的物理来源。
深色模式下要改的只有：frost α 变薄、rim 颜料从白转 gofun、落影转中性黑、纸底翻转。
墨则跟着纸一起翻（濃墨 → 胡粉），理由见上一节。**朱一格不动。**

## 六、一处玻璃，一个数

小球不是"长得像"其它控件，它**就是一枚圆形的 chip**：

| 部位 | token | 亮 | 暗 |
|---|---|---|---|
| 玻璃本体 | `--glass-chip` / `--glass-bg-a` | 0.42 | 0.10–0.14 |
| 白边 | `--glass-rim-a` / `--glass-border-a` | 0.40 | 0.24 |
| 顶光白鳞 | `--glass-spec-a` / `--glass-inset-a` | 0.55 | 0.22 |

`content.js` 的 HSP 采样把 `frostA` 的亮端锚点定在 **0.42**，就是为了让白纸上的球
和 popup 的字段是同一厚度的同一块玻璃。这是"统一"最实在的一条。

---

## 七、落影的和弦

每一道阴影都是同一个三段和弦，只有落距随高度变：

```
inset 白边      玻璃边缘接住光
0 0 0 1px 墨    发丝接触环
两道墨色落影     近 + 远
```

`--sh-chip` / `--sh-panel` / `--sh-float` / `--sh-pearl` / `--sh-channel` 全部按此配。

---

## 八、时序

不对称是高级感的来源：**按下瞬时且线性，松开走弹簧**。
同一条曲线用在小球、popup 字段、开关旋钮和下拉透镜上。

**位移按像素对齐，不按比例。** 小球 `scale(0.96)` 在 64px 上边缘走约 2.6px；
同样的比例放到 246px 宽的字段上会是"一整块在抽动"，所以字段用 `0.99`、
18px 的旋钮用 `0.92`——三处落在同一个 1–3px 的位移带里，手感才是同一个。
按下的落影走 `--sh-chip-press`：落影收成 2px 接触晕、顶光白鳞暗一档，
和小球 `:active` 少掉的正好是同两样东西。

```css
--spring:    cubic-bezier(0.34, 1.56, 0.64, 1);
--t-release: 0.22s var(--spring);   /* 松开 */
--t-press:   0.08s ease-out;        /* 按下 */
--t-color:   0.16s ease-out;
```

halo 的入场/退场也是非对称的：入场从内侧收紧、过冲、落定；
退场向外漂散，opacity 先走（0.42s）、transform 后落（0.58s）——"光先散、形后收"。

## 九、文件与边界

| 文件 | 作用 |
|---|---|
| `theme.css` | **唯一真相来源**。`:root, :host` 双选择器：`:root` 给两个扩展页面，`:host` 给 FAB 的 shadow root |
| `content.css` | 小球本体。theme.css 被 fetch 后**前置拼接**进同一个 `<style>`，所以读的是同一批 token |
| `popup.html` / `options.html` | `<link rel="stylesheet" href="theme.css">`，`<body class="pointer-scene">` |
| `content-page.css` | **唯一读不到 theme.css 的文件** |

`content-page.css` 被注入宿主页面的 `<head>`，在那里声明 `:root` 自定义属性会把
Pointer 的调色板泄漏进站点（并和站点自己的撞名）。所以它的数值是**手写的副本**，
不是独立的选择。文件头部列了需要同步的对照表——改 `theme.css` 时一并改它。

## 十、加东西之前先问

1. 它是纸、是玻璃、还是墨？**答不上来就别做。**
2. 如果是墨——它有没有变成一块面？（变了就是错的）
3. 它的颜色能不能从 `theme.css` 的 token 里拿？（拿不到，说明要么该加 token，要么该改设计）
4. 它有色相吗？**除了报错的那支朱，答案必须是"没有"。**
5. 深色模式下我需要写覆盖块吗？（如果需要的不只是落影，多半说明 token 没用对）
6. 如果它是信号墨——这一处是主角还是配角？**一个物件上只能有一处是主角。**
   三处配角各自都"不算重"，叠起来照样把墨变成面。
