# 划词翻译 — 所有选区情况

---

## 一、什么都不做（直接跳过）

| # | 你做了什么 | 为什么跳过 |
|---|-----------|-----------|
| S1 | 扩展没开，或者正在拖动悬浮按钮 | 翻译功能没激活，不该响应 |
| S2 | 鼠标点了一下但没选中文字（空选区） | 没有内容可翻译 |
| S3 | 选中了翻译悬浮按钮上的文字 | 那是 UI 本身，不是页面内容 |
| S4 | 上一次翻译还没返回，又选了同一段文字 | 正在翻译中，防止重复请求 |
| S5 | 在一个已翻译的结果里面选了一部分文字 | 选区的起点和终点都在同一个翻译 span 里，已经翻译过了 |
| S6 | 起点和终点分别在不同的翻译 span 里，但范围内只命中了 1 个 span，且选区完全被它包含 | 还是属于"在已翻译内容内部"的情况 |
| S7 | 选区的边界恰好等于某个已翻译 span 的边界（精确匹配） | 完全一样的范围，不需要再翻 |

## 二、选区碰到了已翻译的内容（混合选区）

> 选区内既有已翻译的部分，又有没翻译的部分。

**进入条件：** 选区范围内找到了至少一个已翻译 span。

### 具体子情况：

| # | 情况 | 处理方式 |
|---|------|---------|
| M1 | 选区一头在普通文字，一头拖进了已翻译区域 | 还原旧翻译 → 重新翻译整段 |
| M2 | 选区从一个已翻译 span 拖到了另一个已翻译 span，中间有未翻译文字 | 还原所有碰到的旧翻译 → 重新翻译整段 |
| M3 | 选区跨越了已翻译内容，但选区里其实没有任何未翻译的新文字 | 不做任何事，跳过 |
| M4 | 还原旧翻译后，剩下的文字 trim 完是空的 | 只做清理（删 marker），不发翻译请求 |

### M1/M2 的处理流程：

1. 把选区扩大，完整包住所有被碰到的已翻译 span
2. 在扩大后的范围两端插入标记节点（marker）
3. 把范围内所有已翻译 span 还原回原文
4. 对还原后的纯文本重新翻译，走下面两条路之一：
   - 还原后内容在**多个段落**里 → 按段落拆开，每段独立翻译（M5）
   - 还原后内容在**一个段落**里 → 作为单块翻译（M6）
5. 清理标记节点

| # | 还原后的情况 | 走哪条路 |
|---|-------------|---------|
| M5 | 还原后内容跨了多个块级元素（比如两个 `<p>`） | 拆成多段，每段各自调用"同块合并翻译" |
| M6 | 还原后内容都在同一个块级元素内 | 直接走"同块合并翻译" |

## 三、选区全是未翻译的新内容

### 情况 A：选中了一个词或一句话（单文本节点）

> 最常见的场景。比如在一个 `<p>` 里选了其中几个字。
> 判断标准：`range.startContainer` 和 `range.endContainer` 是同一个文本节点。

- 把这段文字发给 API 翻译
- 翻译回来后，原来的文本节点被拆成三段：`前面没选的文字` + `翻译结果 span` + `后面没选的文字`

### 情况 B：选中了多个节点，但都在同一个段落里

> 比如 `<p>普通文字<strong>加粗文字</strong>普通文字</p>`，你选中了跨越加粗标签的一整段。
> 判断标准：选区起点和终点所在的块级元素（`<p>`、`<li>`、`<h1>` 等）是同一个。

- 收集选区内所有文本节点
- 用分隔符 `__AI_TRANSLATOR_DELIM__` 把它们拼成一个字符串，一次发给 API
- API 返回后按分隔符拆开，逐个文本节点替换成对应的翻译 span
- `<a>`、`<strong>`、`<em>` 等内联标签保持不动，不会被破坏

**fallback：** 如果 API 返回的结果按分隔符拆不对（数量不匹配），自动降级到情况 C 的方式重试。

### 情况 C：选中了跨段落的内容

> 比如从第一个 `<p>` 选到第二个 `<p>`，或者从标题选到正文。
> 判断标准：选区起点和终点所在的块级元素不是同一个。

- 收集选区内所有文本节点
- 每个节点的文字作为独立的翻译单元，打包成数组一次发给 API
- API 返回同样数量的翻译结果，逐个节点替换

### 情况 D：多节点但找不到所属的块级元素

> 比如文字直接放在 `<body>` 下面，没有被 `<p>`、`<div>` 等包裹。
> 判断标准：`closest(blockSelector)` 返回 null。

- 视为跨块情况，走情况 C 的逻辑（逐节点独立翻译）

## 四、翻译中的异常保护

| # | 什么时候发生 | 怎么处理 |
|---|------------|---------|
| E1 | API 请求发出前，文本节点已经从页面上消失了 | 放弃翻译，释放锁，清理 loading |
| E2 | API 返回后，原来的文本节点不在页面里了（比如用户在等待期间操作了页面） | 放弃替换，或降级到结构化翻译 |
| E3 | API 返回后，文本节点的内容变了（offset 对不上） | 尝试在当前文本里重新定位原文，找到唯一匹配就用新位置替换，找不到就放弃 |
| E4 | 分隔符翻译结果拆分数量不对 | 降级到逐节点独立翻译（情况 C） |
| E5 | Chrome 扩展上下文失效 | 弹窗提示用户刷新页面 |
| E6 | 远程 API 服务器没有设置 Key，或当前 API 地址/Key 尚未一起验证 | 弹窗说明缺少的配置并打开设置页；本机/私有局域网服务器允许空 Key |

## 五、决策流程图

```
用户松开鼠标（mouseup）
  │
  ├─ 没激活 / 空选区 / 在按钮上 / 并发锁命中 → 跳过
  │
  ├─ 完全在已翻译 span 内 / 精确匹配已翻译 → 跳过
  │
  ├─ 选区里有已翻译 span？
  │   ├─ 有，但没有未翻译的新文字 → 跳过 (M3)
  │   └─ 有，且有新文字 → 还原旧翻译，重新翻译
  │       ├─ 还原后跨多个段落 → 按段落拆开，每段合并翻译 (M5)
  │       └─ 还原后在同一段落 → 单块合并翻译 (M6)
  │
  └─ 选区全是未翻译内容
      ├─ 单个文本节点 → 简单翻译 (A)
      ├─ 多节点，同一段落 → 分隔符合并翻译，保留内联标签 (B)
      │   └─ 分隔符拆分失败 → 降级为逐节点翻译 (C)
      └─ 多节点，跨段落或无块级父元素 → 逐节点独立翻译 (C/D)
```

## 六、翻译后页面上发生了什么

所有路径最终都做同一件事 — 把文本节点替换成翻译 span：

**翻译前：**
```html
<p>This is some text here</p>
```

**选中 "some text" 翻译后：**
```html
<p>This is <span class="ai-translator-highlight" data-pointer-extension-owned="translation">一些文字</span> here</p>
```

- 原文、译文、显示状态和 group ID 保存在扩展内部的 `WeakMap`，不会暴露成页面可读的 DOM 属性
- `data-pointer-extension-owned="translation"` 只用于限定扩展自有节点和样式边界
- 点击译文时，同一 group ID 的翻译会一起切换原文/译文
- 如果选区只选了文本节点的一部分，节点会被拆成 `前缀文本节点 + 翻译span + 后缀文本节点`

## 七、并发保护

| 时机 | 发生了什么 |
|------|-----------|
| 翻译请求发出前 | 把涉及的文本节点加入锁集合 |
| 翻译成功 / 失败 / 报错 | 把文本节点从锁集合中移除 |
| 新的选区进来 | 检查选区内的文本节点是否在锁集合中，如果有重叠就跳过 |
